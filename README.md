# dsh-observer — 副脑 / 孵化主脑

> **`v1.2.1`（2026-11-05）— 初始态无身份 → 磋商 → 孵化主脑（带武器库）**
>
> 新会话默认**没有身份**。用户先和它谈需求；当工作大到**一个上下文窗口装不下**时，它调用 `observer_spawn_main` 孵化出一个主脑，自己成为副脑。小任务它自己直接做完，不孵化。
>
> 孵化时会**先向 dsh-memory 取经**：用方案作查询词检索既有技能与负知识，连同方案一起打包注入 —— 主脑一睁眼就带着「执行计划 + 武器库 + 避坑指南」。
>
> 上一代（`v1.1.0`，Plan B）的「主脑召唤副脑」入口 `observer_create` 仍然保留，用于反向场景。

## 核心功能

- **`observer_spawn_main`（工具，孵化入口）**：发起会话把**已确认的方案**交出去 —— 宿主在**同一工作区**创建新会话（主脑），**先检索记忆库取回相关技能/负知识**，再把「方案 + 武器库」以 `developer/message` 注入（**上下文消息，不是 prompt → 主脑保持休眠**），给两半打上 `[主脑]` / `[副脑]` 标题，记录**带角色的双向绑定**，`sessionId` 通过工具返回值直接回到模型。
- **`observer_create`（工具）**：反向 —— 主脑召唤一个跟随它的副脑。
- **`observer_bind` / `observer_status` / `observer_consult`（工具）**：手工绑定、只读状态、不绑定任何主会话的「前置需求磋商副脑」。
- **`observer-spawn`（斜杠命令）**：手动入口；走命令通道，**每次会留一行**，这是该通道的固有代价。
- **双向转生跟随**：监听 `graft/session-transferred`，**任意一半**被切片时只改指针，另一半不动、不等待。

## 为什么「互相转生」不再死锁

副脑在转生链里**不是节点**。主会话切走时只改指针，不参与切片、不退休。死锁需要两方**互相等待**，而这里：

| 传统互转生的死锁 | 本设计 |
|---|---|
| A 退休等 B 转移、B 转移等 A 退休 | 谁都不退休，也不等对方 |
| 两把源锁顺序不一致导致互锁 | 只写自己的绑定表，不碰对方的锁 |
| 转生期间读主日志读到半截 | 副脑读的是日志，不写主会话 |
| 点火 → 目标又触发自身转生 | 指针联动只发生在 `session-transferred` 之后 |

## 已知结构性限制（为什么没有按钮）

这是本项目三轮失败后得到的结论，详细复盘见同级文档《副脑插件架构复盘与底层缺陷报告-2026-11-05.md》：

| 编号 | 限制 | 后果 |
|---|---|---|
| **D1** | 第三方 Client **没有插件自有 Remote** | 客户端无法定向、静默地请求本插件做事 |
| **D2** | `commands.execute` **是广播**，且回执形状不稳定 | 任何「请求-应答」控制流都会污染会话流，且拿不到返回值 |
| **D3** | 会话**归属**（workspace/cwd）只有宿主有权威数据 | 客户端建会话必然产生「选择工作区」孤儿页 |

**结论**：副脑只能由**模型工具**（值直达模型）或**宿主侧动作**触发；UI 按钮路线在 0.2.2 上不可行，除非宿主补上插件自有 Remote（typert 构建期声明）。

## 工具一览

| 工具 | 作用 |
|---|---|
| `observer_spawn_main` | **孵化入口**：把已确认的方案交给新主脑，本会话成为副脑 |
| `observer_create` | 反向：主脑召唤一个跟随它的副脑 |
| `observer_bind` | 为已存在的会话补写指针（手工/历史场景） |
| `observer_status` | 只读绑定表；`ackFocus: true` 消费一次性焦点请求 |
| `observer_consult` | 开一个不绑定主会话的「前置需求磋商副脑」 |

## 绑定表结构（v1.2.0）

一个**配对（pair）**一行，带角色；两个方向都有索引：

```json
{
  "pairs": {
    "<observerId>|<mainId>": {
      "observerSessionId": "...", "mainSessionId": "...",
      "at": 0, "origin": "incubated | summoned"
    }
  },
  "pairOf": { "<observerId>": "<observerId>|<mainId>", "<mainId>": "<observerId>|<mainId>" },
  "bindings": { "<mainId>": "<observerId>" },
  "reverse": { "<observerId>": "<mainId>" }
}
```

角色是**存储的事实**，不是从位置推导出来的 —— 孵化会在运行时反转两者的角色。`pairOf` 保证**一个会话只属于一个配对**（有测试逐个不变量校验）。

## 配置

```yaml
- id: dsh-observer
  name: dsh-observer
  config:
    bindingsPath: "C:\\Users\\<you>\\.dsh\\profiles\\<profile>\\data\\dsh-observer\\observer-bindings.json"
```

`bindingsPath` 建议显式给出：desktop 宿主不把 `DSH_PROFILE_DIR` 传给 Electron 主进程，不写会回落到默认路径。

**当前：64 / 64。** 覆盖：

- **孵化**（14 条）：在发起会话自己的 cwd 创建主脑、方案作为 `developer/message` 注入且**从不 prompt**、配对记录带角色且双向索引、两半各自打标题、空方案拒绝、无工作区拒绝且不创建、create 抛错如实上报、已是主脑不能再孵化；
- **记忆调度**（6 条）：武器库**追加**在方案之后（不是替换）、查询词与 workspace 都来自方案与发起会话、`semantic:false`（不在 create 内部做 LLM 往返）、**没有 dsh-memory 时照样孵化**（缺席 ≠ 失败）、错误结果与空 hint 都不伪造段落、配对照常记录；
- **双向转生**：主脑被切片 → 副脑跟随；副脑被切片 → 主脑跟随；焦点永远指向主脑；无关转生不动任何东西；**一个会话只属于一个配对**（不变量逐个校验）；
- **绑定**：标题驱动绑定、重复标题不重复注入、无 id 拒绝；
- **客户端**：无 UI、无建会话、无命令、无重命名、无轮询。
